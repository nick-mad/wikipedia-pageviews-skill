# wikipedia-pageviews: навичка AI-агента для дослідження інтересу до тем

Навичка у форматі [Agent Skills](https://agentskills.io/specification). З нею агент відповідає
засновникам B2C-продуктів на питання на кшталт «чи зростає інтерес до теми X у мовному
розділі Y і чи можна цьому вірити?» або «яку мову запускати наступною?». Відповіді
спираються на [Wikimedia Pageviews API](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/reference/page-views.html).
Навичка будує графіки й збирає PDF-звіт на одну сторінку.

- Директорія навички: [`wikipedia-pageviews/`](wikipedia-pageviews/). Усе лежить у ній: `SKILL.md`, код, тести, evals, приклади.
- Приклади звітів: [`wikipedia-pageviews/examples/`](wikipedia-pageviews/examples/)
- Методологія: [`wikipedia-pageviews/references/methodology.md`](wikipedia-pageviews/references/methodology.md)

## Швидкий старт

Потрібен лише [`uv`](https://docs.astral.sh/uv/). Python і залежності він підтягне сам
з `uv.lock`, скомпільованих файлів у репо немає.

```bash
# підключити навичку до Claude Code (або будь-якого агента з підтримкою Agent Skills)
mkdir -p ~/.claude/skills && ln -s "$PWD/wikipedia-pageviews" ~/.claude/skills/wikipedia-pageviews

# або викликати CLI напряму
wikipedia-pageviews/scripts/wpv resolve "intermittent fasting" --langs pl,cs
wikipedia-pageviews/scripts/wpv analyze --topic "Intermittent fasting=Q1666254" --langs pl,cs
wikipedia-pageviews/scripts/wpv report wpv-output/intermittent-fasting_pl-cs --headline ... --summary ... --recommendation ...

# тести (офлайн, на записаних відповідях API)
cd wikipedia-pageviews && uv run pytest
```

Змінна `WPV_CONTACT` задає контакт у User-Agent: політика Wikimedia вимагає вказувати
контакт. `WPV_CACHE_DIR` задає, де лежить кеш (за замовчуванням `~/.cache/wikipedia-pageviews`).

## Як це працює

```
запит користувача
   │
   ▼
SKILL.md ── короткий сценарій для агента: які команди, як читати результат, як відповідати
   │
   ├─ wpv resolve   тема → кандидати Wikidata (QID) + які мови мають статтю
   ├─ wpv analyze   QID × мови × період → analysis.json + chart.png + стислий підсумок у stdout
   ├─ wpv show      повторно показати збережений підсумок (без мережі)
   └─ wpv report    analysis.json + текст агента → PDF на 1 сторінку (з перевіркою чисел)
```

Ключові рішення:

1. **Код робить усю роботу з даними, агент лише інтерпретує.** Слабка модель не пише
   HTTP-запити й статистику з нуля. Вона викликає 2–3 команди й читає підсумок, де числа
   вже округлені так, як їх варто цитувати. Кожен висновок супроводжує вердикт
   (growing / declining / flat / unclear), рівень довіри та список причин «чому».
2. **Одна тема — один об'єкт Wikidata.** Назву статті в кожній мові бере з sitelinks
   Wikidata, тож порівнюються еквівалентні статті, а не вгадані агентом назви. Якщо в мові
   статті немає, це повідомляється як окремий висновок, а не мовчки пропускається.
   Приклад: у польській Вікіпедії немає статті про інтервальне голодування. Для таких
   випадків є явні «статті-замінники» (`pl:Назва`); вони позначаються, а довіра до них
   знижується.
3. **Перегляди редиректів додаються.** Інакше перейменування статті виглядало б як обвал
   інтересу.
4. **Нормалізація на весь мовний розділ.** Загальний трафік Вікіпедії падає на 10–30% на
   рік (пошукові сніпети, AI-відповіді). Без нормалізації майже будь-яка тема «падає».
   Основна метрика — частка статті від усіх переглядів розділу (views per million), сирі
   перегляди показано поруч.
5. **Статистика, стійка до новин.** Нахил Сена (Sen's slope) і тест Манна-Кендалла з
   поправкою Yue-Wang на автокореляцію. Сплески виявляються через robust z-score
   (median/MAD). Піки, що повторюються щороку (вересень для астрономії), позначаються як
   сезонність, а не новини. Порівняння «останні 12 міс. vs попередні 12» прибирає
   сезонність.
6. **Прозора довіра.** До 5 балів: довжина ряду, значущість, узгодженість метрик, стійкість
   до сплесків, обсяг трафіку. Кожен бал має текстову причину, яку агент цитує.
7. **Ранжування з вагами користувача.** «Для нас важливіший розмір аудиторії» → `--weights volume=0.6,...`.
   Складники (growth / volume / trust) видно завжди.
8. **Звіт не може містити вигаданих чисел.** Графік, таблиця й застереження генерує код.
   Агент пише лише заголовок, висновок, рекомендацію й наступні кроки. Кожне число в цьому
   тексті звіряється з `analysis.json` (з урахуванням округлень, `1,234` vs `1 234`,
   `12K`). Якщо число не знайдено, PDF не створюється, і агент бачить, які саме числа
   прибрати.
9. **Повторні й пов'язані запити дешеві.** SQLite-кеш: дані за завершені місяці кешуються
   назавжди, решта має TTL. «Додай словацьку» довантажує лише нові ряди.
   `wpv show` повертає підсумок без мережі.
